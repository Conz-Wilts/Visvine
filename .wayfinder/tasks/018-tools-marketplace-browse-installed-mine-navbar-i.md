## Task

The one marketplace destination. **Navbar.tsx**: add a 'Tools' icon button next to the calendar icon (same size/hover language; a simple 'blocks/puzzle' SVG) linking to `/tools`; visible to every signed-in member (installing is admin-gated inside).

**app/(auth)/tools/page.tsx** → `<Marketplace/>` from features/tools/components/marketplace/. Tabs `Browse | Installed | Mine` in the URL (`?tab=`), using the pane-top tab bar if the shell allows outside /directory (look at how /admin's ConsoleShell mounts its top tabs and reuse that pattern) — otherwise a local tab bar in the page header. All fetches via **features/tools/lib/client.ts** (fetchJson helpers typed with lib/tools/api.ts DTOs).
- **Browse**: search box + cards (title, description, author, version, install count, perimeter chips via `PerimeterSummary`, 'Installed' badge). Card → detail drawer/modal: full description (index.md body rendered with the app's markdown renderer), perimeter, version history, **Install** (admins) → `InstallDialog`: slug field, requirements checklist (`computeRequirements`-based list from the POST result or a preview call — show ✓/✗ per connector/type/agent with 'will run degraded' copy), type-claim conflicts picker, confirm.
- **Installed** (admins see controls, members read-only): rows with enable toggle, degraded banner + 'Re-check', pending upgrade card showing `PerimeterSummary` with the diff + 'Approve upgrade', type claims editor (which type this tool pages/tabs), uninstall.
- **Mine**: the caller's authored tools in this space (from `/authoring`): build status (ok/errors count), version, last published status (pending/approved/rejected + reviewer note), buttons: Open (→ `/directory/tool:<name>`), Preview (→ `/tools/preview/<name>`), Publish (admins; shows a confirm with the perimeter summary), and a 'New Tool' explainer card pointing at the MCP flow (copyable `get_tool_sdk` hint) — no in-app builder.
States: loading skeletons, empty states, error toasts using existing primitives in apps/web/components/ui. Acceptance: tsc/lint/knip clean; walk each tab against `pnpm dev` (report screenshots or a description).

## Outcome

The `/tools` marketplace is live: a navbar icon beside the calendar, one destination with Browse / Installed / Mine in the URL, and every fetch through `features/tools/lib/client.ts` typed off `lib/tools/api.ts`. tsc, `eslint . --max-warnings=0` and knip are all clean repo-wide (knip's two remaining entries are tasks 045 and 015/016's, not mine) and `pnpm test` is 943/943. I walked all three tabs against `pnpm dev` as both an admin and a member with real published/installed/authored data, and found and fixed one real bug doing so.

**Navbar.** A blocks/puzzle SVG next to the calendar, same 48px `shell-icon-btn` chrome, `shell-icon-btn--active` on `/tools*`. Gated on `canAccessFeature(featureConfig, 'tools', isAdmin)` rather than shown unconditionally: the task says "every signed-in member", and that is what this is — installing is admin-gated inside — but a space that switched Tools OFF (or locked the key to admins) must not show it, because `useFeatureRouteGuard` would bounce that member straight back off the page. With no space selected the icon still shows: the registry is global and Browse works without one.

**Tabs.** `?tab=browse|installed|mine`, `router.replace` so tabbing doesn't stack history. The shell does allow the pane-top bar outside /directory (that is what /admin's ConsoleShell does), so it uses the same chrome — `sticky -top-4 -mt-4 -ml-6`, `PaneTopScrollbarMask`, and the shared `UnderlineTabs` with `handoffKey="pane-top"`, so the underline hands off from the Directory/notes/console bars. ConsoleShell itself is not reused: it hardcodes `?section=` and wraps everything in `ConsoleSaveProvider` + a SaveStatus this page has no use for.

**Browse** — debounced server search, cards (title, name·version, description, `PerimeterSummary` chips, author, install count, "Installed" badge from `installedInSpace`), cursor paging. Card → detail modal: `index.md` body through react-markdown + remark-gfm + rehype-sanitize (the message feed's pipeline, headings shifted down a level, `img` dropped — this text is authored by a stranger), declared reach, "where it appears", version history, Install for admins. **InstallDialog**: slug field validated against `TOOL_NAME_RE` with a note when the space already holds that slug, a `computeRequirements`-based checklist run client-side over the space's real connectors/node types/agents (the same pure function the server runs, so preview and outcome agree — node types come off the space DTO, connectors and agents from their own routes; a dimension the space won't answer for reads "not checked" rather than inventing a missing dependency), the "will run degraded" copy, and a per-type page/tab picker that previews both server rules (built-in pages stay built in; one install owns a type's page). The POST's own `conflicts`/`downgraded`/`degraded` are what actually get reported, as toasts.

**Installed** — enable toggle, degraded banner over `describeRequirements` + Re-check, pending-upgrade card that lazily fetches the incoming version so `PerimeterSummary` can draw the full perimeter with `pendingVersion.perimeterDiff` layered on (green added / struck-through red dropped) + Approve upgrade, type-claims editor, uninstall behind `ConfirmDialog`. Members get the identical list read-only — toggle disabled, claims as plain text, no Re-check/upgrade/uninstall (the server also strips `pendingVersion` for them). Every mutation re-reads the list AND calls `refreshSpace()`, since the rail row lives on the space record.

**Mine** — build status (Builds / N errors with the first three diagnostics / Not built), config parse errors, version, Open → `/directory/tool:<name>`, Preview → `/tools/preview/<name>`, admin Publish behind a confirm that restates the perimeter the reviewer will see plus an optional note, and a "New tool" explainer card with a copyable `get_tool_sdk` — no in-app builder. It reuses `toolDiagnosticLine` from task 019's `BuildDiagnostics.tsx` rather than keeping the copy of it I first wrote.

**Toasts** are a small portalled stack built on the existing `Alert` primitive (errors persist, the rest retire after 6s) — there was no toast primitive in `components/ui` to reuse. Loading skeletons and empty states throughout; note `EmptyState` renders `description ?? title`, so every description here is written to stand alone.

**Bug found and fixed during the walkthrough.** The Mine tab intermittently showed *another space's* tools. `useSpace()` settles on the stored current space one render after mount, so a visit reliably issues two reads — one for whichever space came first, one for the real one — and they do not come back in order. `Marketplace` now guards both loaders with a monotonic run token so only the newest read lands (BrowseTab already had one). Reproduced, fixed, re-verified. Two smaller fixes from the same pass: the type-claim `<select>` was clipping "Own the page", and four empty-state descriptions restated their titles.

**Live walkthrough** — dev server on :3000, admin@local.dev (space + super admin) and member@local.dev. **One piece of the brief I could not build in scope, filed as task 046.** Mine is specified to show "last published status (pending/approved/rejected + reviewer note)" from `/authoring`, and that route's `AuthoredToolSummary` simply does not carry it — it has the note's `version:` and the build, nothing from the registry.
