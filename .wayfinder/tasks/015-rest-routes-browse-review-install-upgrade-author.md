## Task

Thin route handlers over lib/tools/{registry,installs,service}.ts, in the house style (see apps/web/app/api/communities/[spaceId]/connectors/* and agents/*): `requireSession()`, `isAdmin(userId, spaceId, email)` for admin actions, `isSuperAdmin(email)` for review, zod-validated bodies, JSON envelopes with named keys.

- `GET /api/tools/registry?q=&cursor=` → `{ versions: BrowseItem[] , nextCursor }` (approved latest per key, plus `installedInSpace?: boolean` when `?spaceId=` is given).
- `GET /api/tools/registry/[versionId]` → `{ version: { …public fields, config, perimeter, perimeterDiff, uiSource? (only for super-admins or the author), history: [{version, status, reviewedAt}] } }`.
- `GET /api/tools/review` (super-admin) → `{ queue: [...pending with author, key, version, perimeter, perimeterDiff] }`; `GET /api/tools/review/[versionId]` → full detail incl. before/after sources for the CodeDiff; `POST /api/tools/review/[versionId]` `{ decision: 'approved'|'rejected', note? }`.
- `GET /api/communities/[spaceId]/tools` (member) → `{ installs: InstallSummary[] }` (non-admins get the list without pending upgrade details); `POST` (admin) `{ versionId, slug?, typeClaims? }` → `{ install, conflicts }`.
- `PATCH /api/communities/[spaceId]/tools/[installId]` (admin) `{ enabled? | typeClaims? | applyUpgrade?: true | recheck?: true }`; `DELETE` uninstall.
- `GET /api/communities/[spaceId]/tools/authoring` (member) → `{ tools: AuthoredToolSummary[] }`; `GET …/authoring/[name]` → `{ tool: detail incl. sources + build }`; `POST …/authoring/[name]` `{ action: 'publish', note? }` (admin) → `{ version }` or 409 with the build errors when not ok.

**lib/tools/api.ts** — the DTO types shared with the client (`BrowseItem`, `VersionDetail`, `InstallSummary` re-export, `AuthoredToolSummary`) so UI tasks import types from one place (must not import React). Acceptance: tsc/lint/knip clean; exercise each route once with curl against `pnpm dev` using a dev-login cookie (document the calls you made in the outcome).

## Outcome

**Routes.**
- `GET /api/tools/registry?q=&cursor=&spaceId=` → `{ versions, nextCursor }`. Global and signed-in-only. `?spaceId=` adds `installedInSpace` per row — that flag is space data, so a named space goes through the full member + `tools`-feature gate, while the catalogue itself needs only a session. The flag is ABSENT (not `false`) when no space was named, so the UI can tell "not installed" from "didn't ask".
- `GET /api/tools/registry/[versionId]` → `{ version }` = public fields + `config`, `indexSource`, `perimeterDiff`, `previousVersion`, `history[{version,status,reviewedAt}]`. Two narrowings beyond the brief's letter: a version that is NOT approved 404s for anyone but the author or a super admin (404, not 403 — an unshipped snapshot should not be discoverable by the shape of the refusal), and `dataSource` is gated exactly like `uiSource`. The task named only `uiSource`, but leaking half a Tool's code while withholding the other half is not a rule anyone could defend.
- `GET /api/tools/review` (super admin) → `{ queue }`, each row a summary + `perimeterDiff` + `previousVersion`. One diff query per row rather than a join: the queue is pending rows only, and the diff needs a *different* previous-approved lookup per key anyway.
- `GET /api/tools/review/[versionId]` → `{ version, previous }` where `previous` is the last approved version's three sources — the "before" side of task 020's `CodeDiff`, null for a first submission. `POST` `{ decision, note? }` → `{ version, upgraded }`.
- `GET /api/communities/[spaceId]/tools` (member) → `{ installs, isAdmin }`; non-admins get every row with `pendingVersion: null` (proved live: the same install reads `null` for the member and carries the id + perimeter diff for the admin). `POST` (admin) → `{ install, conflicts, downgraded }` — `downgraded` is a superset of the task's `{ install, conflicts }`, and task 018's install dialog needs it to say why a `page` claim became a tab.
- `PATCH /api/communities/[spaceId]/tools/[installId]` takes exactly one of `enabled | typeClaims | applyUpgrade | recheck` (zod `.refine` counts the defined keys) — each is a separate decision with its own refusals, and a request that both enabled a Tool and took its type page would have no honest status code. `recheck` answers `{ install, installs }` because `refreshRequirements` is a whole-space pass; it is addressed per-install because that is where the degraded banner's button lives. `DELETE` uninstalls.
- `GET …/tools/authoring` → `{ tools }`; `GET …/authoring/[name]` → `{ tool }` (sources + build); `POST …/authoring/[name]` `{ action:'publish', note? }` (admin) → 201 `{ version, warning }`, or **409 `{ error, build }`** when the working copy does not compile — refused in the route off the detail it already fetched, so the author gets the diagnostics rather than a sentence about them.

**Two files worth flagging.** (1) `lib/tools/api.ts` re-exports `InstallSummary` / `AuthoredToolSummary` / `AuthoredToolDetail` and adds `BrowseItem`, `VersionDetail`, `VersionHistoryEntry`, `VersionSources` and one envelope interface per route. Every route annotates its response body with its envelope, so the types are load-bearing on the server side too — a change to a shape is a type error on both ends, and knip stays quiet because nothing is exported into the void. (2) **Out of scope, deliberately: I added `apps/web/lib/tools/route.ts`** (34 lines) — `requireToolsAccess(spaceId)` + `bad()`, the exact shape of `lib/agents/route.ts`. Four of my routes need the same four-step preamble (session → member-resolved context → the `tools` feature key → principal), and re-exporting a helper out of a Next.js `route.ts` is not a thing you should do. This also closes the REST half of the gap task 042 closed for the bridge: a space that switched Tools off now refuses installs and authoring reads too, not just frames.
